# Collaboration & Sponsorship

Ananas is building an open, cloud-native **conversational work engine** with provider-portable routing, governed tools/skills, persistent project context, durable artifacts, reproducible evaluations, and reusable vertical packs.

The engineering workspace, Codespaces/GCP setup, benchmarks, and skill/MCP work support that product; they are not the product definition by themselves.

## Collaboration priorities

1. Portable skills/tool adapters that can be used from Ananas Core without vendor lock-in.
2. MCP integrations that improve real project/work workflows.
3. Project/file context, provenance, artifact, and execution interoperability.
4. Reproducible model/tool/orchestration benchmarks and cost/reliability telemetry.
5. Provider-portable LiteLLM routing and failover.
6. Secure Codespaces/GCP development and deployment automation.
7. Vertical-pack integrations, beginning with DIRT RCM, that prove domain specialization without core forks.

## Upstream-first contribution policy

- Fix upstream when the issue belongs upstream.
- Fork only when Ananas must maintain a deliberate, documented divergence.
- Record every canonical upstream in `config/upstreams.yaml`.
- Use `.ananas/upstreams/` only as a local Git-ignored pinned source cache.
- Preserve license and attribution requirements.
- Prefer small, reviewable changes backed by tests, PoC evidence, or benchmark results.
- Do not promote an upstream component merely because it was fetched locally.

## Partnership targets

- NVIDIA: Agent Skills, Nemotron/NIM routes, and evidence-based evaluation of NeMo Agent Toolkit.
- Continue: skill/rule/MCP interoperability and developer workflow integration.
- Vercel skills ecosystem: portable skill distribution.
- Microsoft: skills/MCP interoperability.
- Model Context Protocol ecosystem: reference-compatible tools/resources/prompts.
- Google Cloud and GitHub: cloud development, deployment, identity, CI/CD, and project governance.
- Healthcare/RCM design partners: DIRT workflow validation after privacy/security gates are met.

## What Ananas can offer partners

- Open compatibility adapters.
- Reproducible benchmark/evaluation results.
- Real cloud-native reference implementations.
- Bug reports and upstream patches with evidence.
- Cross-provider routing and cost/reliability evidence.
- A concrete core → vertical architecture demonstrated first through DIRT.

## Readiness rule

Partnership/sponsorship claims should follow evidence:

- working integration;
- public or reproducible evaluation evidence;
- security/privacy boundary documentation;
- clear product stage (PoC, Prototype, MVP, Pilot/Beta);
- measurable reliability/cost outcomes;
- external/pilot usage when relevant.

Do not present a prototype as market validation or infrastructure completion as product adoption.
